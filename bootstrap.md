# Bootstrap: sim2real Pipeline Setup

Machine-readable task list for bootstrapping this experiment repo to work with
the sim2real transfer pipeline at `github.com/inference-sim/sim2real`.

## Prerequisites

- sim2real framework repo checked out locally (referred to as `$SIM2REAL`)
- Access to `https://github.com/llm-d/llm-d-router`
- Python 3.11+ with PyYAML

## Tasks

### task-1: Derive target component repository

**status:** pending
**depends:** none
**action:** derive-and-approve
**expect:** exactly 1 candidate (if >1, open an issue before proceeding)

Scan the experiment folder for references to the target component repository.
Present the candidate(s) to the user for approval before proceeding.

**scan sources:**
- Go import paths in `algorithms/*.go` and code blocks in `README.md`
  (pattern: `github.com/<org>/<repo>/...`)
- Commit references in `config.md` tables (column: "Component" or "llm-d")
- Any existing `.gitmodules` file

**extract for each candidate:**
- `repo_url`: full GitHub URL (e.g., `https://github.com/llm-d/llm-d-router`)
- `repo_name`: last path segment (e.g., `llm-d-router`)
- `ref`: pinned commit if found (e.g., `a10f9ac8`)
- `evidence`: list of file:line where the reference was found

**present to user:**
```
Derived target component(s) from folder:

  1. https://github.com/llm-d/llm-d-router @ a10f9ac8
     evidence:
       - README.md:81  (import "github.com/llm-d/llm-d-router/pkg/...")
       - README.md:67  ("Build from llm-d-inference-scheduler (aka llm-d-router) at commit a10f9ac8")
       - config.md:123 (llm-d | a10f9ac8)

Approve this as the target component? [y/n]
```

**if >1 candidate:** halt and open an issue:
```
Multiple target component candidates detected:
  1. github.com/llm-d/llm-d-router @ a10f9ac8
  2. github.com/llm-d/llm-d-inference-scheduler @ <unknown>
This bootstrap only supports a single target. Please resolve and re-run.
```

**on approval, output:** store as shell variables for subsequent tasks:
```bash
COMPONENT_URL="https://github.com/llm-d/llm-d-router"
COMPONENT_NAME="llm-d-router"
COMPONENT_REF="a10f9ac8"
```

### task-3: Generate baseline scenario(s)

**status:** pending
**depends:** none
**action:** derive-and-approve

Generate llm-d-benchmark scenario YAML file(s) for the baseline arm(s). These
describe the model deployment configuration (hardware, vLLM args, replicas) in the
format the sim2real pipeline expects.

**reference script:** `generate_scenarios.py` in
`github.com/inference-sim/sim2real-config-exploration-validation/sim2real/`
Copy this script locally if not already present — it may need adaptation per
experiment.

**derivation process:**
1. Scan the experiment folder for deployment configuration:
   - Look for structured config files (e.g., `config.md`, `config.yaml`, JSON)
   - Extract: model name, hardware type, replica count, vLLM arguments
2. Map extracted values to llm-d-benchmark scenario schema using lookup tables
   in `generate_scenarios.py`:
   - `MODEL_METADATA`: model name → shortName, path, size, maxModelLen
   - `HARDWARE_LABELS`: hardware key → nvidia.com/gpu.product label value
   - `build_additional_flags()`: vllm_args → `--flag=value` strings
3. Write scenario YAML(s) to `baselines/`

**output schema** (per baseline file):
```yaml
scenario:
- name: <lowercase-alphanumeric, no hyphens>

  model:
    name: <model HuggingFace ID>
    shortName: <derived from lookup>
    path: <derived from lookup>
    huggingfaceId: <same as name>
    size: <storage estimate>
    maxModelLen: <from lookup or config>
    blockSize: <from vllm_args>
    gpuMemoryUtilization: <from vllm_args>

  decode:
    replicas: <from config>
    acceleratorType:
      labelKey: nvidia.com/gpu.product
      labelValue: <from hardware lookup>
    vllm:
      additionalFlags:
      - "--flag=value"
      ...
```

**present to user:**
```
Generated N baseline scenario(s):
  1. baselines/<name>.yaml — <model> on <N>x <hardware>
     [show key fields: replicas, TP, max-num-seqs, etc.]

Approve? [y/n/edit]
```

**verify:**
```bash
for f in baselines/*.yaml; do
  python3 -c "import yaml; yaml.safe_load(open('$f'))" && echo "OK: $f"
done
```

**constraints:**
- Scenario names must be lowercase alphanumeric only (1-20 chars, no hyphens).
  The manifest validator enforces this.
- If the generate script produces names with hyphens, they must be sanitized.

### task-4: Select workloads for transfer.yaml

**status:** pending
**depends:** none
**action:** derive-and-approve

Identify which workload files to include in the sim2real transfer run.

**derivation process:**
1. List all YAML files in `workloads/`
2. For each, extract key metadata: rate, client mix, token distributions
3. If simulation results exist (in `results/`), cross-reference to identify
   which workloads showed meaningful effect vs dormant (no difference from baseline)
4. Propose a subset — prefer workloads where the algorithm had measurable impact

**present to user:**
```
Found N workload files. Recommended for transfer:

  Include:
    - workloads/X.yaml — <reason: showed N% improvement in sim>
    - workloads/Y.yaml — <reason>

  Exclude (dormant — no sim effect):
    - workloads/Z.yaml — baseline=treatment under capacity

Include all / use recommended subset / custom selection?
```

**output:** ordered list of workload paths for the `workloads:` section of
transfer.yaml.

### task-5: Create transfer.yaml

**status:** pending
**depends:** task-2, task-3, task-4
**action:** derive-and-approve

Assemble the sim2real transfer manifest from outputs of prior tasks.

**derivation process:**
1. Set `scenario` from the experiment folder name (or README title)
2. Set `component` from task-1 outputs ($COMPONENT_NAME, $COMPONENT_REF)
3. Derive `component.kind` from the algorithm source:
   - Scan Go source in `algorithms/` for interface references
   - `UsageLimitPolicy` / flowcontrol → `kind: EndpointPickerConfig`
   - `Scorer` / scheduling → `kind: EndpointPickerConfig`
   - `Admission` → `kind: AdmissionPolicyConfig`
4. Derive `component.build.commands`:
   - Standard Go: `["go build ./cmd/epp/", "go test ./pkg/...relevant-path/..."]`
   - Scan algorithm imports to determine the test path
5. List `baselines` from task-3 output (files in `baselines/`)
6. List `algorithms` from source files in `algorithms/`:
   - Each `.go` file with a `Factory` function or plugin registration pattern
     is a candidate algorithm entry
   - `source`: relative path to the file
   - `defaults`: typically `"baseline"` (derive treatment from baseline config)
7. Set `workloads` from task-4 output
8. Set `context.files`: list files in the experiment root that contain deployment
   config or signal mapping info (e.g., README.md, config.md, any *-context.md)
9. Derive `context.text`: summarize from the algorithm source what interface is
   targeted and where in the component repo the plugin should be placed

**output schema:**
```yaml
kind: sim2real-transfer
version: 3

scenario: <derived>

component:
  repo: <$COMPONENT_NAME>
  kind: <derived from algorithm interface>
  ref: <$COMPONENT_REF>
  base_image:
    hub: <derived from component repo org, e.g., ghcr.io/llm-d>
    name: <$COMPONENT_NAME>
  build:
    commands: <derived from algorithm imports>

algorithms:
  - name: <lowercase-alphanumeric>
    source: <relative path to algorithm .go file>
    defaults: baseline

baselines:
  - name: <from task-3>
    scenario: <path to baseline YAML from task-3>

workloads: <list from task-4>

context:
  text: <derived summary of target interface and placement>
  files: <list of context-bearing files in experiment root>
```

**present to user:**
```
Assembled transfer.yaml:
  scenario:   <value>
  component:  <repo> @ <ref> (kind: <kind>)
  algorithms: <N> (<names>)
  baselines:  <N> (<names>)
  workloads:  <N> files
  context:    <N> files, text: "<first line>..."

Review full content? [y/show/edit]
```

**verify:**
```bash
python3 -c "
import sys; sys.path.insert(0, '$SIM2REAL/pipeline/lib')
from manifest import load_manifest
m = load_manifest('transfer.yaml')
print(f'OK: scenario={m[\"scenario\"]} baselines={len(m[\"baselines\"])} algorithms={len(m[\"algorithms\"])}')
"
```

**constraints:**
- `component.repo` must equal the local submodule directory name (= `component.path`).
- All package names (baselines, algorithms) must be lowercase alphanumeric only,
  1-20 chars, no hyphens or underscores.
- `context.files` paths are resolved relative to `$EXPERIMENT_ROOT`.
- `component` is required when `algorithms` is non-empty.

### task-6: Verify pipeline can load manifest

**status:** pending
**depends:** task-5
**action:** shell

Run prepare.py in dry-check mode to validate the manifest and prerequisites.

```bash
export SIM2REAL=/path/to/inference-sim/sim2real
python3 $SIM2REAL/pipeline/lib/manifest.py transfer.yaml 2>&1 || true
# Or use the full pipeline with --help to check it parses:
python3 -c "
import sys; sys.path.insert(0, '$SIM2REAL/pipeline/lib')
from manifest import load_manifest
m = load_manifest('transfer.yaml')
print('Manifest valid')
print(f'  scenario: {m[\"scenario\"]}')
print(f'  component.path: {m[\"component\"][\"path\"]}')
print(f'  component.ref: {m[\"component\"].get(\"ref\", \"none\")}')
print(f'  baselines: {[b[\"name\"] for b in m[\"baselines\"]]}')
print(f'  algorithms: {[a[\"name\"] for a in m[\"algorithms\"]]}')
print(f'  workloads: {m[\"workloads\"]}')
print(f'  context.files: {m[\"context\"][\"files\"]}')
"
```

**verify:** Exit code 0 and all fields printed correctly.

## Automation Notes

by scanning the folder, proposing values, and pausing for approval at each
`derive-and-approve` step. Approval gates:
- task-1: target component repo
- task-3: generated baseline scenario(s)
- task-4: workload selection
- task-5: assembled transfer.yaml

**Task 6** (validation): confirms the manifest loads correctly before proceeding.
